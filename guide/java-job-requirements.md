# 第十一部分：Java 招聘要求判断

## 11.1 本章目标

读完本章后，你应该能：

1. 判断一个 Java 岗位是否值得投递
2. 区分"硬性要求"和"加分项"
3. 知道哪些关键词不必因为技术栈不同而放弃
4. 诚实评估自己的匹配度

---

## 11.2 岗位要求分类

### 🟢 可以直接投递

满足以下条件之一即可投递：

- 要求"Java/Python/Go/Node.js 至少掌握一种"
- 要求"熟悉 Spring Boot"（你学完本教程后已掌握基础）
- 要求"有 Java 项目经验"（你有实战项目）
- 要求"熟悉 REST API 开发"（你的前端经验完全适用）
- 要求"熟练使用 MySQL"（你有数据库基础）
- 要求"了解微服务架构"（了解概念即可，不是必须深入）

**关键词：** "至少掌握一种"、"熟悉"、"了解"、"有基础"

### 🟡 补一点知识就可以投递

需要补充 1-2 周学习的：

- 要求"熟悉 Spring Cloud"（需要了解 Gateway、Nacos、Feign 等组件）
- 要求"有 Redis 使用经验"（需要了解缓存策略、分布式锁）
- 要求"有消息队列经验"（需要了解 Kafka/RabbitMQ 基本概念）
- 要求"熟悉 Linux 常用命令"（需要补充基础操作）
- 要求"有 Docker 容器化经验"（你可能已经会了）

**策略：** 投递后快速补充相关知识，面试时诚实说"有基础了解，正在深入学习"。

### 🔴 暂时不适合投递

需要较长时间积累的：

- 要求"5年以上 Java 开发经验"
- 要求"精通 JVM 调优"（需要深入理解 GC、内存模型）
- 要求"有高并发、高可用系统设计经验"（需要实际项目积累）
- 要求"有大型分布式系统架构经验"
- 要求"精通多线程编程"（需要深入理解并发包）
- 要求"有大数据处理经验"（Hadoop、Spark、Flink 等）

**策略：** 不投递，但可以把这些作为长期学习目标。

---

## 11.3 关键词解读

### "熟悉 Java"

**含义：** 能独立写代码，理解面向对象，会用集合框架。

**你的情况：** ✅ 学完本教程后已满足。

### "掌握 Spring Boot"

**含义：** 能独立开发 REST API，理解 IOC、DI、AOP 概念。

**你的情况：** ✅ 学完第五、六、九章后已满足。

### "有 Java 项目经验"

**含义：** 做过实际的 Java 后端项目，不是只有 Demo。

**你的情况：** ✅ 第九章的实战项目可以作为项目经验。

**面试时怎么说：** "我用 Spring Boot + MyBatis-Plus 独立开发了一个学习时间记录系统，包含用户鉴权、CRUD、分页查询、数据统计等功能。"

### "熟悉微服务"

**含义：** 了解微服务架构理念，知道服务拆分、服务发现、配置中心。

**你的情况：** 🟡 需要补充 Spring Cloud 基础知识。但你的 NestJS 模块化经验可以类比。

**面试时怎么说：** "我对微服务架构有概念性了解，之前的项目中使用过模块化拆分。Spring Cloud 的具体组件我正在学习。"

### "熟悉 Spring Cloud"

**含义：** 需要用过 Gateway、Nacos、Feign、Sentinel 等组件。

**你的情况：** 🔴 需要较长时间学习。但如果岗位只是"了解"级别，可以投递。

### "熟悉 JVM"

**含义：** 理解 JVM 内存结构、GC 算法、类加载机制。

**你的情况：** 🔴 暂时不需要深入。这不是入门级要求。

### "有高并发经验"

**含义：** 处理过 QPS 1000+ 的系统，用过缓存、消息队列、限流等。

**你的情况：** 🔴 需要实际项目经验积累。

### "Java/Python/Go 至少掌握一种"

**含义：** 他们不限定语言，侧重工程能力。

**你的情况：** ✅ 你掌握 Python 和 Java 基础，完全符合。

**这类岗位最值得投！** 他们看重的是工程能力，而不是特定语言。

---

## 11.4 不必因技术栈放弃的岗位

以下岗位即使写了"Java"，你仍然可以投递：

### 1. 全栈工程师 / 全栈开发

> "熟悉 Java/Node.js/Python 中至少一种后端语言"

**分析：** 他们需要的是全栈能力，不是特定语言专家。你的前端经验是加分项。

### 2. AI 应用开发工程师

> "有 Python 或 Java 后端开发经验，熟悉 API 开发"

**分析：** AI 应用开发的核心是 Python，Java 只是部分业务系统的技术栈。你的 Python + Java 组合是优势。

### 3. 后端开发工程师（初级/中级）

> "熟悉 Java 或 Python，有 Web 后端开发经验"

**分析：** 初级岗位不要求深度，你的经验足够。

### 4. 前端工程师（偏全栈）

> "熟悉前端技术，有 Node.js 或 Java 后端经验者优先"

**分析：** 你是前端工程师，Java 是加分项，不是必须项。

---

## 11.5 面试时如何诚实描述自己的 Java 水平

**推荐话术：**

> "我的主要技术栈是 TypeScript 和 Python，最近系统学习了 Java 和 Spring Boot。我用 Spring Boot + MyBatis-Plus 独立完成了一个 REST API 项目，包括用户鉴权、数据库 CRUD、分页查询等功能。我能够独立修改 Controller、Service、DTO、Entity 等常见代码，能看懂项目中各层的职责。如果遇到复杂的 Java 问题，我会借助 AI 和文档快速解决。"

**关键点：**
1. 诚实说明你的主要技术栈
2. 描述你具体做了什么（而不是"我学过"）
3. 说明你的能力边界（能做什么，不能做什么）
4. 展示你的学习能力（借助 AI 和文档）

---

## 11.6 投递策略总结

| 要求 | 判断 | 动作 |
|------|------|------|
| 只要 Java 基础 + Spring Boot | 🟢 直接投 | 展示你的实战项目 |
| 要求 Spring Cloud、微服务 | 🟡 可投 | 投递后快速补充基础概念 |
| 要求 JVM 调优、高并发 | 🔴 不投 | 作为长期学习目标 |
| Java/Python/Go 至少一种 | 🟢 优先投 | 这是最适合你的岗位 |
| 全栈工程师 | 🟢 优先投 | 你的前端经验是优势 |
| AI 应用开发 | 🟢 优先投 | Python 为主，Java 是加分项 |

## 11.8 结语

你不需要成为 Java 专家才能投递 Java 岗位。

你需要的只是：
1. 能看懂 Java 代码
2. 能独立写简单的接口
3. 能理解项目的分层架构
4. 能在 AI 的帮助下快速解决问题

这 11 章教程已经帮你完成了这个目标。

**下一步：** 如果你遇到真实的 Java 项目，回顾本教程的对应章节，然后借助 AI 开始写代码。你会发现自己比想象中快得多。
